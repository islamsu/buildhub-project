WHAT WAS BUILT (the five authorized items, nothing else)
================================================================================

REAL VENDOR DIRECTORY
  /marketplace/vendors no longer renders a hard-coded array of fictional
  companies. server/vendorDirectory.ts reads genuine provider accounts through
  an explicit column allowlist. Mock-only fields (order counts, years in
  business, "recommended" badges) were removed rather than fabricated for real
  accounts.

SHARED TAXONOMY + VENDOR DECLARATIONS
  shared/rfqCategories.ts promotes the nine category values the RFQ form
  already used, so creation and targeting can't drift. Vendors self-declare;
  no role-to-category mapping was invented.

DETERMINISTIC TARGETING
  Exact-match OR eligibility. An unclassifiable RFQ is eligible for NOBODY: it
  stays visible in the ordinary listing but never becomes a targeted qualified
  enquiry. Six of the eight RFQs in the verification DB have category = NULL,
  so this fallback isn't hypothetical.

COUNTING + LIMITS
  Listing is free; only opening a lead spends a credit, once ever per
  vendor+RFQ. FREE 5 / PROFESSIONAL 30 / PREMIUM unlimited, enforced from the
  authenticated user inside the transaction.
