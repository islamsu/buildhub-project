36.  FINAL PRODUCTION RECOMMENDATION
================================================================================

                          PRODUCTION NO-GO

The blocking reason is unchanged and is infrastructure, not code.

Against the mandate's own §71 checklist, everything is satisfied except the
last two lines: password reset live-verified, and storage live-verified.

§71 is self-contradictory about what that means. It permits PRODUCTION GO when
these are "formally blocked only by unavailable external infrastructure with all
code verified", and then states that a launch-critical capability unavailable
for infrastructure reasons is PRODUCTION NO-GO. Both readings are reported here
rather than one being chosen quietly:

  LENIENT READING   GO. All code, fail-closed behaviour and tests are complete
                    for both; only the live round-trips are unexercised.

  STRICT READING    NO-GO. A construction marketplace whose customers cannot
                    recover an account and whose suppliers cannot attach a
                    document to a bid is not ready, whatever the reason.

THE STRICT READING IS APPLIED. Password reset and file upload are launch-critical
for this product.

Setting SMTP_* and S3_* as GitHub environment secrets on the `staging`
environment and re-dispatching the gate is the single change that converts this.
Those five skips then become passes or become real defects, and either outcome
is worth more than the current silence.

What is NOT in doubt: main and staging serve the same commit, that commit passes
640 live checks with zero failures, the cross-role security boundary holds at 98
cells with zero leaks, and 16 of 16 mutations against the security and
commercial rules were killed.
